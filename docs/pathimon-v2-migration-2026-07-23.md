## 1. 프로젝트 구조 요약 (배경)

패시몬은 인하대 의대 감염·면역 강의를 원본으로 하는 포켓몬류 학습 게임이다.

### 1-1. ★ 전투 규칙 — 패시몬끼리는 싸우지 않는다

**이 프로젝트에서 가장 착각하기 쉬운 설계 원칙이다.**

- **전투는 패시몬 vs 보스·트레이너에서만 성립한다.** 보스와 트레이너는 병원체가 아니라 **인체의 방어·치료 행위**를 의인화한 존재다
- **야생 패시몬은 포획 대상일 뿐 싸우지 않는다.** 야생 조우에서 할 수 있는 것은 `지나간다` · `캡슐` · `도감` · `패시몬` 넷이고 **`싸운다`가 없다**(`ui/battleUi.ts`의 `battleActionOptions`)
- 층 배치: 5의 배수는 트레이너, 10의 배수는 보스, 나머지는 야생(`encounterKindForFloor`)
- **한 판에 전 종이 등장하지 않는다.** 야생 로스터 81종에 야생 층은 80층뿐이라 매 판 몇 종은 빠진다. 이는 정상이며, 야생은 **활성 패시몬 풀에서 무작위로 뽑는다**는 것이 설계다. 로스터는 판마다 셔플된다(`createDistributedWildRoster`)
- `resolveSwitchMonster`도 야생이면 적 턴 없이 교체만 하고 끝난다(`battle/turn.ts`)
- `resolvePlayerMove`에 **야생 조우를 거부하는 가드**를 넣었다. 규칙이 UI에만 있으면 함수를 직접 부르는 쪽에서 깨지기 때문이다

> **주의:** 이 규칙을 모르면 테스트를 잘못 고치게 된다. 실제로 `runState.test.ts`의 6개 테스트가 야생 조우에서
> `resolvePlayerMove`를 직접 호출하고 있었고, 전부 트레이너 층(5층) 기반으로 옮겼다.
> 야생 적의 체력을 고정해 테스트를 통과시키는 식의 대처는 **존재하지 않는 시나리오를 유지보수하는 것**이라 하면 안 된다.

파서가 v2 노트의 데이터를 **여러 경로로 조용히 버리고 있었다.** 전부 수정했다.

1. **`firstMappedTag`는 첫 번째로 매핑되는 값만 상성 태그로 쓴다.** 그래서 `structure: 외피보유, DNA바이러스` 순서가 중요하다.
   `DNA바이러스`는 `none`으로 매핑되므로 앞에 두면 인터페론 상성이 죽는다. 헤르페스 5종이 전부 `외피보유`를 앞에 둔 이유다.
2. `TagValue`에 대응이 없는 location 값(**담관·간·뇌·눈·근육·림프계·피하·나선균**)은 **일부러 매핑하지 않았다.**
   다음 토큰으로 넘어가게 두어 억지 매핑으로 상성이 틀어지는 것을 막는다. `딸낭조충`·`하이퍼클렙`의 `간`이 그 사례다.

### 2-5. `data/pathimonNoteData.ts` — 기생충 진화 패턴 반영

`createParasiteEvolutionMonsters`가 **기생충 노트를 예외 없이 유충→성충으로 쪼개고 있었다.**

```ts
function evolutionPattern(noteText: string): string | undefined {
  return noteText.match(/^-\s*패턴:\s*([A-D])\b/m)?.[1];
}
```

- **패턴 B(유충 정점)** → 성충 단계를 만들지 않는다. 충란형(딸낭조충)은 충란→유충에서, 유충형(아니사키·가시악구·기어가기)은 유충 하나로 끝
- **패턴 C(분기 진화)** → 단계를 아예 만들지 않고 이름도 손대지 않는다. `리본돼지`(장 성충)와 `물혹돼지`(낭미충)는 각각 종점이다
- 패턴 A·D는 기존 동작 유지. v1 노트에는 `- 패턴:` 줄이 없어 `undefined`로 떨어지고 기존 동작을 유지한다
- 회귀 테스트 2건: `stops larva-peak parasites…`, `leaves branching parasites…`

**남은 오탐:** `startsFromEgg`(`pathimonNoteData.ts`)가 `이름:\s*충란`으로 **기술 이름까지** 검사한다.
`은어흡충`의 전용기를 `충란 위장`→`난개 위장`으로 개명해 피했지만 정규식 자체는 그대로다. 앞으로 기술명에 `충란`을 앞세우면 안 된다.

### 2-6. `state/factory.ts` — `abilities: []` 불일치 수정

`evasion: 없음` 노트는 템플릿에 `abilities: []`인데 런타임에서 `['none']`이 되어 어긋났다.
`.filter((a) => a !== 'none')`와 `abilities[0] ?? 'none'`으로 맞췄다.

### 2-7. ★ 적 공격 배율 — 반감·무효를 두지 않기로 확정

**적 → 패시몬 배율은 ×4 / ×2 / ×1 세 단계뿐이다.**

| 판정 | 배율 | 근거 |
|---|---|---|
| 효과가 굉장하다 | ×4 | 노트 `대처법:`의 약제명이 기술 `targetTags`에 적중 (직접 처치) |
| 효과가 있다 | ×2 | 노트 `증상/태그:`가 적중 (간접) |
| 보통 | ×1 | 아무것도 안 걸림 |

**반감(×0.5)·무효(×0)·곱연산은 없다.** 패시몬의 `evasion`을 비롯한 방어 태그는 **배율에 걸리지 않고 학습 텍스트로만** 쓴다.

작업 경위를 남긴다 — 같은 길을 두 번 가지 않기 위해서다.

1. `claudecode/MATCHUP.md` §1이 ×2/×1/**×0.5/×0** + 곱연산을 규정하고 §4가 evasion 반감·무효 열을 **"전투 상성의 핵심 축"** 이라 부르고 있었다
2. 코드는 처음부터 ×1·×2·×4만 냈다. 문서와 코드가 갈라져 있었고, 나는 **문서를 정본으로 보고 코드를 문서에 맞췄다**
3. 사용자 판단으로 **문서 쪽이 틀린 것**으로 정리됐다. 이유는 두 가지다 —
   **(a)** 어떤 조합이 무효고 어떤 게 반감인지 유저가 표를 따로 외워야 하는 규칙이 된다. **×4와 ×1의 격차만으로 학습 신호는 충분하다.**
   **(b)** 위력이 고정된 구조라 ×0이면 적의 턴이 통째로 날아간다 — 학습이 아니라 답답함이 된다.
   (구충제가 세균에 안 듣는 것은 약리학적으로 맞지만, 메트로니다졸처럼 원충·혐기성 세균을 함께 잡는 예외도 있어 칼로 자를 축도 아니다.)
4. 코드를 되돌리고 **`MATCHUP.md`를 v2.2로, `VOCAB.md`를 v2.6으로 개정**했다(§3)

되돌린 지점:

- `battle/bossMatchup.ts` — `bossMoveEffectiveness`를 `1 | 2 | 4` 반환으로 복원. `BossEffectivenessKind`도 `normal`·`effective`·`super` 3종으로
- `battle/turn.ts` — `resisted`·`immune` 로그 문구 제거
- `battle/effectiveness.ts` — `defenseTypeMultiplier` 추출을 되돌려 `calculateMultiplier` 원형 복원
- `data/effectiveness.ts` — 적 기술 계열 행 9개(`oxidative` + 약물 8종) 삭제, 패시몬 방어 특성 항목(`cyst`·`larval_migration`·`tissue_migration`·`acid_tolerance`·`iron_piracy`) 전부 제거

> **★ `EFFECTIVENESS`는 패시몬 → 적 방향 전용이다.** 보스의 방어 특성 8종(상피장벽·점액섬모·위산·정상균총·철제한·항독소·수용체결핍·면역조절)이
> 내 기술을 반감·무효화하는 쪽은 **원래부터 동작 중이고 이번에 손대지 않았다.** 노트 `타입:` 26종이 AttackType 5개로 접히고
> (`special`·`lysis`·`toxin`·`spread`·`immune_mediated`), 그 5행에 보스 방어 특성 8종이 전부 들어 있다.
> 예: 독소 기술이 `항독소`를 가진 보스에게 ×0.

> **남은 죽은 코드(삭제하지 않음).** `EFFECTIVENESS`의 `phago`·`opsonin`·`antibody`·`complement`·`ctl`·`th1`·`th2`·`interferon` 8행은
> **전부 적 기술 타입**이라 어느 방향에서도 조회되지 않는다. 협막·항산성·잠복 같은 패시몬 방어 특성이 값으로 들어 있는 것이 구 시스템의 흔적이다.
> 파일 상단 주석에 명시해 뒀다. **정리 여부는 사용자 판단 대기.**

회귀 테스트: `keeps pathimon evasion traits out of the matchup table` — 방어 특성 7종이 상성표에 다시 들어오면 실패한다.
