# 패시몬 PWA·100층 엔딩·피드백 설계

## 목적

패시몬을 모바일 홈 화면에 설치해 게임 앱처럼 실행할 수 있게 하고, 100층 클리어 후 전용 엔딩과 별점 피드백 화면으로 연결한다.

완료 조건은 다음과 같다.

- GitHub Pages 배포판을 iOS·Android에서 PWA로 설치하고 실행할 수 있다.
- 설치형 PWA와 일반 모바일 브라우저 모두 가로 화면에서 동일한 게임 경험을 제공한다.
- 모바일 전투 화면에서 방향 패드와 A/B 버튼이 다시 표시되고 정상 입력된다.
- 100층 클리어 후 정비구역이나 101층으로 가지 않고 3페이지 엔딩과 피드백 화면으로 이동한다.
- 피드백은 모바일 PWA에서도 Web3Forms를 통해 메일로 전송된다.

## 범위

### 포함

- PWA manifest, 서비스 워커, 설치 아이콘과 앱 셸 캐시
- 가로 화면 권장 및 세로 화면 회전 안내
- 노치와 모바일 브라우저 안전영역 처리
- 모바일 가상 조작계 감지 보완
- 100층 전용 엔딩 씬
- 스토리·보스 대사·엔딩 대사의 타이핑 출력
- Web3Forms 별점·의견 전송
- 네트워크 실패 시 피드백 초안 보존과 재전송

### 제외

- 앱스토어·플레이스토어 네이티브 패키징
- 오프라인 전체 게임 플레이
- BGM·영상·전체 이미지의 서비스 워커 선캐시
- 사용자 계정, 피드백 이력 조회, 답변용 이메일 수집
- 일반 전투 처리 문구의 타이핑 출력

## PWA 구조

### Manifest

`app/public/manifest.webmanifest`를 추가하고 다음 값을 사용한다.

- 이름: `패시몬: 감염과 면역`
- 짧은 이름: `패시몬`
- 시작 주소: GitHub Pages 하위 경로에서 동작하도록 상대 경로 사용
- 표시 방식: `standalone`
- 방향: `landscape`
- 배경색과 테마색: 현재 게임 배경색 계열
- 아이콘: 기존 패시몬 정체성을 유지한 192px·512px PNG

`app/index.html`에는 manifest, theme-color, Apple 모바일 메타데이터와 `viewport-fit=cover`를 연결한다.

### 서비스 워커

서비스 워커는 앱 셸만 캐시한다.

- HTML, JavaScript, CSS, manifest, 설치 아이콘을 캐시한다.
- 새 배포가 설치되면 오래된 앱 셸 캐시를 제거한다.
- BGM, 영상, 대형 패시몬 이미지 묶음은 선캐시하지 않는다.
- `https://api.web3forms.com` 요청은 캐시하거나 가로채지 않고 네트워크로 직접 보낸다.

이 범위는 초기 설치 용량과 모바일 메모리 사용량을 억제하면서 홈 화면 실행에 필요한 최소 기능만 제공한다.

### 모바일 화면

- Phaser의 논리 해상도 `1024×576`과 `FIT` 스케일은 유지한다.
- 가로 화면에서는 `env(safe-area-inset-*)`를 반영해 게임 캔버스가 노치와 시스템 영역을 침범하지 않게 한다.
- 세로 화면에서는 게임 위에 `기기를 가로로 돌려주세요` 안내를 표시한다.
- 회전 안내가 표시된 동안 게임 입력은 차단한다.
- 브라우저가 화면 방향 고정을 지원하면 전체 화면·설치형 실행 시 가로 방향을 요청하되, 실패해도 회전 안내로 대체한다.

### 모바일 가상 조작계

터치 기기 판단은 다음 중 하나라도 참이면 활성화한다.

- Phaser touch 입력 사용 가능
- CSS coarse pointer
- `navigator.maxTouchPoints > 0`

전투, 도감, 상태, 교체처럼 키 입력이 필요한 화면에는 방향 패드와 A/B 버튼을 표시한다. 상점과 파티 선택처럼 화면의 버튼을 직접 터치하는 편이 명확한 화면에서는 기존처럼 가상 조작계를 숨겨 겹침을 방지한다.

## 100층 엔딩

### 진입 조건

- 학습모드와 도전모드 모두 100층 적의 HP가 0이 되면 `EndingScene`으로 이동한다.
- 100층 승리 후 정비구역, 보상 상점, 101층 전투는 시작하지 않는다.
- 마지막 파티 상태를 엔딩 씬에 전달한다.

### 페이지 구성

#### 1페이지

- 화면 중앙에 황금색 `CONGRATULATIONS!`
- 은은한 등장 효과만 사용하고 과도한 장식은 넣지 않는다.

#### 2페이지

- 마지막 파티의 패시몬 이미지를 파티 순서대로 최대 6마리 나열한다.
- 실제 보유 수가 6마리보다 적으면 보유한 패시몬만 표시한다.
- Prof. S의 봉인으로 대체된 패시몬은 현재 런의 상태를 반영해 봉인 인형으로 표시한다.
- 대사:

```text
고마워. 이제 네 세계로 돌려보내줄게.
시험 잘 봐!
```

#### 3페이지

```text
그러나 패시몬 세계에 모든 힘을 쏟은 주인공은
거짓말같이 감면 시험을 망치고 말았다...
```

3페이지가 끝나면 피드백 페이지로 이동한다.

### 타이핑 규칙

- 스토리, 보스 조우 대사, 보스 2페이즈 대사, 100층 전용기 대사, 엔딩 대사는 현재 보스 대사와 같은 빠른 속도인 글자당 24ms로 출력한다.
- 터치·클릭·Enter 첫 입력은 현재 문장을 즉시 완성한다.
- 문장이 완성된 뒤 다음 입력은 다음 문장 또는 다음 페이지로 이동한다.
- 피해량, 상태이상 처리와 같은 일반 전투 문구는 즉시 표시한다.

## 피드백 화면

### 화면 구성

엔딩 4페이지로 다음 요소를 표시한다.

- 제목: `패시몬은 어떠셨나요?`
- 빈 별 5개
- 반투명 다중행 의견 입력창
- `피드백 보내기` 버튼
- `건너뛰기` 버튼
- 전송 상태 문구

별점은 필수이고 의견은 선택이다. 별을 누르면 1번째 별부터 선택한 별까지 황금색으로 채운다.

### 입력 방식

- 모바일 터치로 별과 버튼을 직접 선택할 수 있다.
- PC에서는 마우스와 방향키·Enter를 지원한다.
- 의견 입력은 Phaser 가상 키보드가 아니라 실제 HTML `textarea`를 캔버스 위에 배치한다.
- 입력창은 가로 PWA의 안전영역 안에 놓고, 모바일 키보드가 열릴 때 화면 안으로 스크롤되도록 한다.
- 피드백 페이지에서는 전투용 방향 패드와 A/B 오버레이를 숨긴다.
- 모든 터치 대상은 모바일에서 누르기 충분한 크기를 유지한다.

### Web3Forms 전송

브라우저에서 다음 주소로 JSON POST 요청을 보낸다.

```text
https://api.web3forms.com/submit
```

전송 필드는 다음으로 제한한다.

- `access_key`: 등록된 Web3Forms 공개 액세스 키
- `subject`: `[패시몬] 엔딩 피드백 ★N`
- `rating`: 1~5
- `message`: 사용자가 작성한 의견
- `botcheck`: 빈 값

이메일 주소, 기기 정보, 브라우저 정보, IP 주소를 게임 코드에서 별도로 수집하지 않는다. 액세스 키는 Web3Forms가 브라우저 사용을 전제로 발급한 공개 식별자이므로 클라이언트 설정에 둔다.

도메인 제한 기능을 사용하는 경우 허용 도메인은 프로토콜과 경로를 제외한 `mushpiba.github.io`로 설정한다.

### 전송 상태

- 별점이 없으면 전송 버튼을 비활성화하고 별점 선택을 안내한다.
- 전송 중에는 버튼을 비활성화해 중복 전송을 막는다.
- 성공하면 `피드백을 보내주셔서 감사합니다.`를 표시한 뒤 시작 화면으로 이동할 수 있게 한다.
- 실패하면 입력값을 유지하고 `전송하지 못했습니다. 인터넷 연결을 확인하고 다시 시도해주세요.`와 `다시 보내기`를 표시한다.
- `건너뛰기`는 전송 없이 시작 화면으로 이동한다.

### 모바일 초안 보존

- 별점과 의견은 입력할 때 `localStorage`에 임시 저장한다.
- PWA가 백그라운드에서 종료되거나 네트워크가 끊겨도 다시 피드백 화면에 진입하면 초안을 복원한다.
- 전송 성공 또는 건너뛰기 시 초안을 삭제한다.
- 오프라인 상태에서는 전송을 시도하지 않고 초안을 유지한 채 재시도를 안내한다.

## 상태와 책임 분리

### `EndingScene`

- 엔딩 페이지와 피드백 페이지 전환을 관리한다.
- 마지막 파티의 표시 데이터를 읽는다.
- 타이핑 입력, 별점 선택, HTML 입력창 생명주기를 관리한다.
- 씬 종료 시 HTML 입력 요소와 이벤트를 반드시 제거한다.

### PWA 등록 모듈

- 서비스 워커 지원 여부를 확인하고 등록한다.
- 게임 부팅 실패와 분리해, 서비스 워커 등록 실패가 게임 실행을 막지 않게 한다.

### 피드백 전송 모듈

- Web3Forms 요청 데이터 생성과 응답 성공 여부 판정만 담당한다.
- Phaser 객체에 의존하지 않는다.
- UI는 반환된 성공·실패 결과만 사용한다.

## 오류 처리

- 서비스 워커 등록 실패: 콘솔에만 기록하고 온라인 게임은 정상 실행한다.
- 방향 고정 실패: 세로 화면 회전 안내를 유지한다.
- Web3Forms 네트워크 오류·429·서버 오류: 입력을 보존하고 재시도를 제공한다.
- 로컬 저장소 사용 불가: 현재 화면의 입력은 유지하되 영구 초안 저장 없이 진행한다.
- HTML 입력창 정리 실패 방지: 씬의 shutdown·destroy 이벤트 양쪽에서 동일한 정리 함수를 안전하게 호출한다.

## 테스트

### 단위 테스트

- 100층 승리만 엔딩으로 이동하고 99층 이하는 기존 흐름을 유지한다.
- 최종 파티 표시 데이터가 순서와 최대 6마리 제한을 지킨다.
- 봉인 인형 상태가 엔딩 로스터에 반영된다.
- 타이핑 입력이 `문장 완성 → 다음 문장` 순서를 지킨다.
- 별점 0은 제출 불가, 1~5는 제출 가능하다.
- Web3Forms 요청에 별점과 의견이 올바르게 포함된다.
- 성공·실패 응답과 네트워크 오류가 각각 올바른 상태로 변환된다.
- 모바일 감지가 touch, coarse pointer, maxTouchPoints 중 하나만 참이어도 활성화된다.

### 빌드 검증

- 타입 검사, 단위 테스트, 프로덕션 빌드를 통과한다.
- manifest와 서비스 워커 파일이 배포 산출물에 포함된다.
- 기존 GitHub Pages 상대 경로에서 정적 자산을 정상 로드한다.

### 수동 검증

- 데스크톱 브라우저에서 100층 엔딩 4페이지와 피드백 전송을 확인한다.
- Android Chrome 설치형 PWA에서 가로 실행, 별점, 모바일 키보드, 전송을 확인한다.
- iOS Safari 홈 화면 추가 상태에서 동일 흐름을 확인한다.
- 세로 회전 안내와 노치 안전영역을 확인한다.
- 오프라인 전송 실패 후 온라인 복귀·재전송을 확인한다.
- Web3Forms 수신 메일에 별점과 의견이 도착하는지 확인한다.

## 배포 전 외부 설정

- Web3Forms 액세스 키가 수신 메일과 연결되어 있어야 한다.
- 도메인 제한을 사용한다면 `mushpiba.github.io`가 허용되어 있어야 한다.
- GitHub Pages 배포 후 실제 배포 주소에서 테스트 메일 1회를 보낸다.
