# 포획 OX 퀴즈 재설계 — 설계 문서 (2026-07-25)

## 배경 / 문제

야생 패시몬 포획 시 OX 퀴즈를 낸다. 현재 `createCaptureQuiz(target, catalog)`(app/src/game/learning.ts)는:

- 50% 확률로 **대상의** 학습포인트를 뽑아 정답 O.
- 50% 확률로 **다른 아무 패시몬**의 학습포인트를 뽑아 정답 X (디코이).

구조적 결함 — "이 문장이 이 병원체 것이냐"를 물을 뿐 **참/거짓이 아니다**:

1. **오정보 강제**: 공통 병독인자·공통 치료제·같은 속 문장이 디코이로 뽑히면 대상에게도 **참**인데 정답이 X로 강제된다. 학습 게임에서 치명적.
2. **너무 쉬움**: 계열/병원체가 명백히 안 맞으면 내용을 몰라도 X를 찍는다.

## 목표

- 각 패시몬 노트에 **그 노트의 학습포인트에서 파생한** 포획 OX 문항을 저작한다.
- 정답이 그 병원체 기준으로 확정 → 오정보 강제 제거.
- 직접처치(이 약이 이 병원체를 잡는다)도 OX로 묻는다.
- 새 패시몬 노트 기본 양식에 고정.

## 비목표

- 퀴즈 판정 규칙 변경(맞음→포획 굴림, 틀림→적 반격)은 그대로.
- 자동 문장 생성/자동 부정(코드 레벨)은 하지 않는다 — 거짓 문항은 사람이 저작.

## 노트 스키마 — 새 섹션 `포획 OX:`

학습포인트(`능력치:` 위) 뒤 적당한 위치에 새 섹션을 둔다.

```
포획 OX:
- 페스트균은 그람양성 막대균이다. | X | L1
- 페스트균의 협막은 단백질이라 항체가 붙으면 무력해진다. | O | L2
- 페스트는 스트렙토마이신이나 젠타마이신으로 치료한다. | O | L9
- 페스트는 아시클로버 같은 항바이러스제로 치료한다. | X | L9
- 폐페스트만 호흡기 비말로 사람 간에 직접 전파된다. | O | L7
```

- 형식: `문장 | 정답(O/X) | 근거 L#`.
- **근거 L#** = 그 문장의 참/거짓을 판정하는 학습포인트. 답한 뒤 이 L# 원문을 해설로 보여준다(저작 안 함, 재사용).
- O = 참, X = 거짓.

## 저작 규칙 (데이터 무결성 테스트로 강제)

1. 종당 **4~5문항**.
2. **거짓(X) 문항은 그 노트의 특정 L#을 모순**시켜 만든다. 그 병원체 기준으로 거짓이 확정된다(예: L1 "그람음성" → "그람양성 (X)"). 타 병원체 문장을 끌어오지 않는다 → 오정보 원천 차단.
3. **≥1 문항은 `[치료]` 태그 L# 근거** (직접처치 OX). 오답 처치는 *그럴듯하지만 틀린 계열* 약으로(너무 쉽지 않게).
4. **≥1 거짓(X), ≥1 참(O)** — O/X 혼합.
5. 근거 L#은 반드시 그 노트의 학습포인트에 존재.

## 데이터 흐름

### 타입 (app/src/types/game.ts)
```ts
export interface CaptureQuizItem {
  statement: string;   // 문항
  answer: boolean;     // O=true, X=false
  explain: string;     // 근거 L# 원문(해설). 파서가 해석해 저장.
  sourceL: number;     // 근거 L 번호(무결성 검증용)
}
```
`MonsterData`/`RuntimeMonster`에 `captureQuiz?: CaptureQuizItem[]` 추가.

### 파서 (app/src/data/pathimonNoteParser.ts)
- `포획 OX:` 섹션의 `- 문장 | O/X | L#` 파싱.
- `L#` → profileMemo의 해당 학습포인트 원문 해석 → `explain`.
- L#이 없거나 답 토큰이 O/X가 아니면 파서 에러(빌드 시 잡힘).

### 픽커 (app/src/game/learning.ts)
- `createCaptureQuiz`의 **디코이 경로 폐기**. 새 `pickCaptureQuiz(monster, random)`:
  - `monster.captureQuiz`가 있으면 1개 랜덤 반환.
  - 없으면 **안전 폴백**: 대상 자기 학습포인트 1개를 정답 O 문항으로(오정보 불가). 저작 이행기 동안만.

### UI (app/src/scenes/BattleScene.ts)
- O/X 답 → **해설 1줄 표시**: 맞았는지 + "실제로는 [근거 L# 원문]". 거짓 문항이면 참문장으로 교정.
- 해설 탭/확인 → 기존 `resolveCaptureQuizAnswer(correct)` 진행.
- 판정 규칙 불변.

## 테스트

- 파서 단위: 섹션 파싱, L# → explain 해석, O/X 토큰, 에러 케이스.
- 픽커 단위: 디코이 없음, 폴백 안전(오정보 불가), 저작 항목 랜덤 선택.
- 데이터 무결성: `captureQuiz`가 있는 노트에 대해 규칙 1~5 검증. **집계로 커버리지 보고**.
- 기존 `createCaptureQuiz` 테스트 갱신/제거.

## 시행 단계 (phased)

1. **스키마/파서/타입/픽커/UI/양식/테스트** + 참조 노트 1종(Yersinia pestis) 저작 — 이번 작업.
2. 무결성 테스트는 **`captureQuiz`가 있는 노트만** 규칙 검증(미저작 노트는 폴백으로 안전 동작). 커버리지 집계.
3. 노트 그룹별 배치 저작(대장균 → 살모넬라 → …). 전종 저작 완료 후 무결성 테스트를 "활성 전종 필수"로 강화.
